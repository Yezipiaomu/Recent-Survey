# On-Policy Distillation 总览：定位、分歧与共识

> 调研日期：2026-09-16
> 一句话结论：**OPD 不是一个方法，是一个方法族。
> 五条正交的设计轴决定了两篇都叫 "OPD" 的论文可能在做完全不同的事。**

---

## 0. 为什么需要先定位

"OPD"这个缩写在 2026 年已经严重超载。它至少指代三件不同的事：

| 说法 | 实际所指 | 典型场景 |
|---|---|---|
| "用 OPD 压缩模型" | 强教师 → 弱学生的能力转移 | Thinking Machines 原版、Gemma 2 |
| "用 OPD 做模型固化" | 多个域专家 → 一个统一模型 | DeepSeek-V4、Nemotron 3 Ultra |
| "用 OPD 自我改进" | 单模型带特权信息自教自学（OPSD） | Cursor Composer 2.5、MAI-Thinking-1 |

三者的教师来源、失败模式、超参敏感点都不同。
本文档先建立公共坐标系，再拆分歧轴。

---

## 1. 坐标系：OPD 与邻居的关系

### 1.1 经典四象限（正确但不完整）

Thinking Machines 的原始划分：

| | **稀疏信号**（序列级 reward） | **密集信号**（token 级分布） |
|---|---|---|
| **Off-policy**（教师轨迹） | — | SFT / 经典 KD |
| **On-policy**（学生 rollout） | RL（GRPO / PPO / GSPO） | **OPD** |

OPD 取 SFT 的数据效率 + RL 的分布相关性。原博客的下棋类比很精确：

- **on-policy RL** = 自己下棋但无人指导，每局只有一次胜负反馈，且不告诉你哪步最关键
- **off-policy 蒸馏** = 看大师对局，招法极强，但发生在新手几乎不会遇到的局面里
- **OPD** = 一位对你自己每一步从"昏招"到"妙手"逐一打分的教师

### 1.2 数学上 OPD 就是 RL

在对生成序列做 stop-gradient 的标准假设下，per-position KL 梯度分解为策略梯度形式：

```
per-token advantage:  A_t = 1 + log π_θ(y_t|·) − log π_T(y_t|·)
等价逐 token 奖励:      r_t = log π_T − log π_θ
```

反过来，KL 正则化的 RL 也可以读作蒸馏：向一个"奖励倾斜后的教师"最小化 reverse KL，
等价于在保持靠近当前策略的前提下提升期望奖励。

→ **OPD ≡ 稠密 KL 约束 RL。** 这不是类比，是恒等。

### 1.3 散度选择决定行为

| | 散度 | 性质 | 副作用 |
|---|---|---|---|
| off-policy KD | **forward KL** `D(π_T‖π_θ)` | mass-covering，逼学生覆盖教师全部支撑集 | 给低概率 token 分配质量 → 幻觉 |
| **OPD** | **reverse KL** `D(π_θ‖π_T)` | mode-seeking，收敛到教师少数模式 | 生成多样性下降 |

GKD 作者的建议是 reverse KL 或 JSD(0.9)；但**最优散度是任务相关的**，不存在通用答案。
GKD 还提供 α ∈ [0,1] 混合系数控制蒸馏强度 vs RL 目标（α=1 为纯蒸馏）。

### 1.4 需要打的补丁：参数几何 🟡

2026 年的参数空间分析推翻了"密集监督 ⇒ 密集更新"这个默认假设：

- **Dense Supervision, Sparse Updates**（arXiv:2606.13657）：分析 OPD checkpoint 增量，
  发现密集教师监督**仍然产生稀疏、off-principal 的权重编辑，形似 RLVR 而非 SFT 的密集改写**
- **On the Geometry of OPD**（arXiv:2606.07082）：参数空间诊断把 OPD 定位在
  "relaxed off-principal regime + early subspace locking"，是**介于 SFT 与 RLVR 之间的独立更新几何**
- **Post-Training is About States, Not Tokens**（arXiv:2605.22731）：
  主张按**训练状态来源**而非 loss 形式重划 SFT/RL/OPD，
  以此解释为什么"学生采样的状态"能胜过"退化的教师"

→ **修正后的定位**：OPD 在**监督信号形态**上像 SFT，在**参数更新几何**上像 RL。

## 2. 五条分歧轴

这是判断两篇 OPD 论文是否可比的实操工具。

### 轴 1：Token 粒度——给哪些 token 算 loss

2026 年最拥挤的战场。关键前提（🟢，见 [01](01-mechanism-and-failure-modes.md)）：

> **OPD 的 token 重要性由学生自己的分布决定，无法从教师输出预先算好，必须在线评估。**

这使得 token 选择从根本上区别于 off-policy 的样本筛选。主要流派：

| 流派 | 准则 | 代表 |
|---|---|---|
| 熵准则 | 优先高不确定性 token | Entropy-Aware OPD |
| 散度准则 | 优先师生强烈分歧处 | TIP |
| **可学性准则** | 区分*可学分歧*（教师纠正质量落在学生 top-K 内）与*不可学分歧*（落在支撑集外） | TA-OPD |
| **软重加权** | 先丢低教师似然轨迹，再按"教师置信度 × 学生困惑度"软加权 | FiRe-OPD |
| 序列级 | Beta 核按学生 pass rate 加权，挑中等难度 | PACED、LION |
| **最简估计器** | 只算学生实际采样的那个 token | 大量既有实现的默认 |

⚠️ **冷水**：`Rethinking OPD` §6.3 标题即 *Sampled-Token Reward Is Already Sufficient*（🟢）。
复杂加权方案未必值回成本。

### 轴 2：教师从哪来、怎么信

完整七分法见 [02](02-variant-taxonomy.md)。核心张力：

- **外部 vs 自己**：跨模型转移 vs 单模型自我改进，是两个不同问题
- **白盒 vs 黑盒**：能否拿到 teacher logits，决定只能做 outcome 级还是 logit 级
- **单教师 vs 多教师**：2026 工业界已大幅倒向多教师（见 [03](03-industrial-recipes.md)）
- **信不信教师**：SG-OPD 用 verifier 做信任门控，不默认教师 token 级偏好一致可靠

### 轴 3：目标函数与稳定性

密集 token 信号是卖点也是病根——**原始 KL 容易梯度爆炸**。各家补丁互不兼容：

| 手段 | 代表 |
|---|---|
| batch 内全局归一化 | GNDPO |
| top-K 截断 reverse KL + 长度膨胀修正 | 多家（OvisOCR2 等生产系统也用） |
| 控制变量基线 | vOPD（"KL for a KL"） |
| trust region 约束 | TrOPD |
| PPO-style clipped objective | 已是不少实现默认 |
| 漂移感知截断 | KAT-Coder-V2.5 |

社区论文库里"稳定性/目标函数设计"是条目最多的目标类别之一——**这本身说明 OPD 不稳定是普遍体验**。

### 轴 4：on/off-policy 混合比例

从纯 OPD 到各种混合，无共识默认值：

- **GKD 的 α 混合**：α ∈ [0,1] 调蒸馏 vs RL 目标
- **两段式**：off-policy 冷启 → OPD（Qwen3 的做法，也是 `Rethinking OPD` 推荐的救援配方 🟢）
- **MPD**：学生采轨迹保持推理时分布，大教师把轨迹压缩成简洁推理链
- **DistiLLM-2**：对比式，同时抬教师回复似然、压学生回复似然，离线在线数据并用
- **veRL 的异步 OPD**：**牺牲严格 on-policy 保证换吞吐**（工程侧的混合）

### 轴 5：能不能超过教师

| 立场 | 代表 |
|---|---|
| **天花板派** | 主流隐含假设；`Rethinking OPD` 的"教师须有新知识"条件也偏此 |
| **外推派** | ExOPD（reward extrapolation）、MAD-OPD（多智能体辩论突破天花板） |
| **工业折中** | MOPD 报告称"匹配或超过对应教师"（MiMo-V2-Flash，🟡） |

这条直接关系到 OPD 的定性：**压缩工具，还是能力增长工具**。

## 3. 当前共识与当前争议

### 已形成共识 🟢🟡

1. OPD ≡ 稠密 KL 约束 RL（数学恒等，无争议）
2. off-policy 冷启动几乎总是有帮助——既改善早期优化，**也抬高最终天花板**（🟢 有对照实验）
3. 教师**能力 > 教师规模**（学术与工业独立验证）
4. reverse KL 的 mode-seeking 是 OPD 的默认选择，但非普适最优
5. OPD 比 SFT 和 RL 都更脆弱——实践者的普遍反馈

### 仍在争议

| 争议 | 一方 | 另一方 |
|---|---|---|
| **复杂 token 选择值不值** | TA-OPD 称 5% token 超越全 token（🟠 单一来源） | `Rethinking OPD`：采样 token 已足够（🟢） |
| **OPD 蒸的是能力还是思维模式** | 蒸能力（工业 MOPD 的隐含前提） | 蒸模式（`Rethinking OPD` §3.3 的分布不可区分性）；更极端者：*Does OPD Really Distill?* 认为部分增益来自自我改进而非教师 |
| **能否 scale 到 long-horizon** | agent 方向大量投入 | §6.1 奖励质量随深度退化（🟢） |
| **test-time scaling 的净影响** | 提升采样效率 | **常常收缩高预算下的能力边界**（pass@1 升、pass@k 天花板降，🟡 arXiv:2608.11829） |
| **OPSD 的 collapse 是不是同一回事** | *One Symptom, Three Levers* 主张 collapse 是单一症状的三种杠杆 | 各论文各自命名，术语未统一 |

最后一条值得强调：**OPSD 子领域已经大到需要一篇专门的批判性综述来统一词汇**。

## 4. 怎么读这个领域

给定 579 条目的规模，建议的过滤顺序：

1. **先定位目标**——你要压缩、融合、抗遗忘还是替代 RL？八类目标见 [02](02-variant-taxonomy.md)
2. **再定教师类型**——外部白盒 / 黑盒 / 特权自教师，三条路线文献几乎不交叉
3. **最后才看 token 级技巧**——这层的边际收益可能最小（§6.3）

**起步只需三篇**：Thinking Machines 博客（直觉）→ GKD（原始方法）→ `Rethinking OPD`（机制与救援配方）。
