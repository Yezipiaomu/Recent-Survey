> 调研日期：2026-09-16

## 零、先纠正三个普遍误解

| 误解 | 事实 |
|---|---|
| "端侧缺算力" | **端侧缺的是内存带宽**。移动 NPU 的 TOPS 已接近 2017 年数据中心 GPU（V100 = 125 TOPS） |
| "NPU TOPS 越高跑 LLM 越快" | **TOPS 说明不了 LLM 速度**。解码阶段受内存带宽限制，每个 token 都要流式读全部激活权重 |
| "端侧模型只能 3B" | Apple AFM 3 Core Advanced 已是 20B 总参数、激活 1–4B 的端侧稀疏模型 |

### 内存带宽的数量级差距

| 硬件 | 内存带宽 |
|---|---|
| 移动 NPU | 50–90 GB/s |
| Apple M5 统一内存 | 153 GB/s（较 M4 +30%） |
| 数据中心 GPU | 2–3 TB/s |

**差距 30–50 倍。** 这一个数字解释了端侧 LLM 的几乎所有工程约束。

实测对照：8B 模型在 Snapdragon X Elite 上约 **5–10 tokens/s**，二手桌面 GPU 约 **100 tokens/s**。

## 一、架构层：Transformer 的内部件正在被系统性替换

### 1.1 注意力机制：混合化、线性化、稀疏化

2026 年的现实是——**标准 softmax 注意力不再是默认选项**。

| 路线 | 代表 | 做法 |
|---|---|---|
| **线性 + softmax 混合** | MiniMax-01、Qwen3-Next、Qwen3.5、Kimi Linear | Gated DeltaNet 等线性注意力为主，少量层保留全注意力兜底 |
| **SSM + 注意力混合** | Nemotron、Jamba | Mamba 与自注意力交错 |
| **异构交错窗口** | 多家 | 滑动窗口（128 token）与全局全注意力按 **5:1** 交错 → **KV 缓存需求降 6 倍**，靠可学习 attention sink bias 保长上下文 |
| **改进注意力本身** | Gated Delta-Net（Qwen）、mHC（DeepSeek） | 宣称超越标准注意力 |

**Qwen3.5 的具体配比可作参考**：每 4 层中 3 层线性注意力（Gated DeltaNet）+ 1 层全注意力。

> 端侧架构工程共识：**线性时间注意力或块稀疏模式，把 RAM 控制在 <2GB**。

### 1.2 MoE：稀疏比在极端化

| 模型 | 总参数 | 激活 | 激活比 |
|---|---|---|---|
| Nemotron 3 Nano | 30B | 3B | 10:1 |
| Sigma-MoE-Tiny | 20B | 0.5B | **40:1** |
| Apple AFM 3 Core Advanced | 20B | 1–4B | 5–20:1（剪枝非 MoE） |
| Ring-linear | — | 1/32 | 7× 效率提升 |

**训练策略**：渐进式稀疏化（初期低层多激活专家以稳定训练）+ 渐进上下文扩展（4K → 128K）。

**端侧 MoE 的真实困难**：算得少，但**所有专家都得装进内存**。
这正是量化和 offloading 要解决的，"现有技术有帮助但没有完全解决"。

### 1.3 深细 > 宽浅（小模型特有）

**参数 <1B 时，更多层 + 更小隐藏维度的"深细"结构持续优于"宽浅"结构。**

### 1.4 embedding 参数占比：一个被忽略的效率陷阱

Liquid AI 的观察（值得独立验证）：

| 模型 | embedding 占参数比 |
|---|---|
| Gemma 3 270M | ~63% |
| Qwen3.5-0.8B | ~29% |
| LFM2 | ~10% |

embedding 参数不像其他参数那样贡献推理与知识容量 →
**"有效模型大小"远小于标称参数量**，按参数量横向比较会系统性失真。

### 1.5 扩散 LLM：仍在成熟中

- LLaDA2.0-Uni 统一理解与生成；TIDE 做 MoE 扩散的 I/O 感知专家 offload
- 与投机解码结合可达 **4–6× 加速**（并行解码而非自回归）
- **但未形成端侧主流**，目前主要出现在多模态统一框架里

## 二、量化层：4-bit 是产线标准，2-bit 是研究前沿

### 2.1 主流路线：16-bit 训练，4-bit 部署

| 方法 | 状态 |
|---|---|
| GPTQ / AWQ | 训练后量化事实标准，4× 内存压缩，无显著精度损失 |
| SmoothQuant / SpinQuant | 处理激活值离群点（量化前重塑激活分布） |
| Q4_K_M | **2026 年移动端标准量化档**，保留约 95% 质量，文件降到 1/4 |

**工程实测口径**：int4 相比 fp16 快 2–3×、内存降约 75%，精度轻微损失，多数 NLP 任务的最佳平衡点。

**国内工程案例**：Qwen 7B 经"4bit 量化 + 结构化剪枝"后，
内存 14GB → **2.8GB**，推理延迟 350ms → **85ms**，精度损失约 **2.3%**。

### 2.2 极低比特：1.58-bit 三元化已进入可部署阶段

| 工作 | 贡献 |
|---|---|
| **BitNet b1.58** | 三元权重 {-1, 0, +1}，BitLinear 替换线性投影，匹配 fp16/bf16 Transformer 性能 |
| **Bitnet.cpp** | 三元查找表（TL）+ Int2_Scale（I2_S）；相比全精度 **6.25×** 加速，相比低比特基线 2.32× |
| **BitRL** | RL + 1-bit 量化结合；**10–16× 内存压缩，3–5× 能效提升，保留 85–98% 任务性能** |
| **Bonsai 模型族** | 开权重 1-bit / 1.58-bit 三元模型，规模到 8B |
| **Vec-LUT** | 向量表查找，并行超低比特边缘推理 |
| **TerEffic / TeLLMe** | 三元 LLM 的 FPGA 加速器（TeLLMe 覆盖 prefill + decode） |

**关键发现（ParetoQ）**：2-bit 及以下时，模型学到的是**本质不同的表示**，而非高精度模型的压缩版。
而且 **2-bit 压缩优于「4-bit 压缩的 2 倍参数模型」**。

**限制**：
- ⚠️ BitNet 类模型**必须从头训练，无法对现有模型做后量化**
- ⚠️ Q/K/V 矩阵通常仍保持高精度；部分工作用 RNN 变体替换自注意以做到完全 MatMul-free

### 2.3 NPU 上的量化有额外工序

以联发科天玑 9400 NPU 为例，部署需三步：

```
1. 量化（PTQ 中必须选静态量化 —— 动态量化在 NPU 上性能差）
2. 固定形状图实现（fixed-shape graph）—— 对 NPU 的内存与计算策略至关重要
3. LLM runtime 开发
```

这三步就是前面说的"80% 性能损失来自算子不匹配"的具体落点。

### 2.4 弹性量化（新方向）

本地托管 LLM 的痛点是**内存弹性**——现有方案要么无法小粒度动态调整模型尺寸，要么存储成本过高。
**FlexQuant** 在切换粒度和存储成本上给出可行方向。

## 三、推理优化层

### 3.1 投机解码（端侧收益最大的单项技术）

| 方法 | 加速 |
|---|---|
| Medusa | 2.2–3.6× |
| EAGLE | 无需微调的等效加速 |
| Online SD | 运行时自适应，任意小模型加速任意 LLM |
| 扩散 + 投机解码 | 4–6× |

**MTP（多 token 预测）**在端侧多模态模型中已标准化：复用主模型 embedding 和末层激活做投机解码。

### 3.2 KV Cache：长上下文的真实内存主导项

- 长上下文下 **KV-cache 占用可超过模型权重本身**
- 可量化到 **3-bit**
- 实测故障模式：CPU 推理出现**频繁缺页导致性能骤降**；GPU 推理甚至**设备崩溃重启**
- FlashAttention 系列已进展到 Blackwell 上的 FlashAttention-4

### 3.3 剪枝

| 类型 | 代表 | 端侧可用性 |
|---|---|---|
| 非结构化 | SparseGPT、Wanda | ❌ 难用于端侧硬件（不规则稀疏无法加速） |
| 结构化 | SlimLLM | ✅ 实用方向 |
| 指令跟随剪枝 | Apple AFM 3 | ✅ 已量产 |

### 3.4 推理蒸馏：小模型推理能力的解锁

- DeepSeek-R1 蒸馏产出 1.5B–70B 模型且保留推理能力
- **Qwen3 4B ≈ Qwen2.5 72B** 的能力水平
- MobileLLM-R1 比两倍大小的模型性能高 **2–5×**

> 这是"端侧够用了"这个判断的技术根源。详见同目录调研 `../opd-recently/`（在策蒸馏 OPD）。

## 四、框架与运行时

### 4.1 主流框架对照

| 框架 | 归属 | 强项 | NPU 支持 |
|---|---|---|---|
| **llama.cpp** | 社区 | 最流行、最易扩展、CPU 推理标准 | ❌ 无主流 NPU 后端（LLaDA.cpp 分支为 Hexagon 加了 12000+ 行代码） |
| **MNN / MNN-LLM** | 阿里 | **CPU/GPU 推理速度最优**（KV cache 与权重内存布局优化） | ✅ QNN 路线 |
| **ExecuTorch 1.0** | Meta | 50KB 基础运行时，12+ 后端；KV-cache 量化、滑窗注意力、4-bit 分组量化 | ✅ |
| **MLX** | Apple | Apple Silicon，支持训练 | ❌ 无 ANE 直接访问（只走 GPU） |
| **MLC-LLM** | 社区 | 基于 TVM，跨平台编译 | 部分 |
| **MediaPipe / LiteRT** | Google | Android 官方路径 | ✅ |
| **Foundry Local** | Microsoft | 自动检测硬件、选模型变体、配运行时；`winget install` 即可 | ✅ NVIDIA / Intel / AMD / Qualcomm |
| **mllm** | 社区 | 移动端多模态 | ✅ QNN |

### 4.2 NPU 后端的两条技术路线

```
路线 A：厂商 SDK 委托（GENIE、MNN、mllm）
   → 委托给 Qualcomm AI Engine / Hexagon 栈
   → 省事，但被厂商优化水平锁定

路线 B：自定义内核（llama.cpp 系）
   → 在开源中自己实现算子
   → 灵活可控，工程量巨大
```

### 4.3 必须知道的现实

- **Ollama、llama.cpp、LM Studio 至今不会把聊天推理路由到 NPU**。要用 NPU 得手动转 ONNX + 厂商 EP 编译。
- **Apple Neural Engine 被主流框架普遍忽视**——MLX 走 GPU，llama.cpp 走 CPU+GPU，都没有 ANE 路径。
- **NPU 推理的真实瓶颈是跨后端调度开销和算子 fallback 到 CPU**，硬件加速的收益被这两项侵蚀。
- Intel OpenVINO 2026 春季以预览形态落地，stateless 模式下可驱动 NPU 跑 1–2B 级已验证模型。

### 4.4 NPU 不是通用加速器

Snapdragon 8 Gen 3 的阶段级分析结论：

| 阶段 | 最优硬件 | 原因 |
|---|---|---|
| **Prefill**（计算密集） | **CPU 反而更优** | 并行度高，NPU 调度开销占比大 |
| **Decode**（带宽受限） | NPU 增益**有限** | 瓶颈在内存带宽，不在算力 |

**NPU 的真实价值**：能效显著优于 GPU、不干扰渲染任务、适合小型持续低功耗任务
（后台转写、图像特效、Phi Silica 类小模型）。商业端侧系统仍普遍依赖 NPU——**为了续航，不是为了速度**。

## 五、硬件层

### 5.1 2026 旗舰移动 SoC

| 芯片 | 关键指标 |
|---|---|
| **Snapdragon 8 Elite Gen 5** | NPU 较前代 +37%，每瓦 +16%；12 标量 + 8 矢量单元<br>**新增 GPU↔NPU 直连**（数据交换不过 CPU）<br>3B 模型快 37%，上下文扩到 32K，本地 LLM 吞吐 **220 tokens/s**<br>⚠️ Qualcomm **未公布绝对 TOPS**，网传 80 TOPS 无法追溯来源 |
| **Dimensity 9500** | TSMC 3nm；APU 针对 LLM 和多模态优化<br>常规跑分略低于 8 Elite Gen 5（GB6 单核 3635 vs 3831，多核 10941 vs 12459）<br>每瓦性能明显不及 Qualcomm |
| **天玑 9300 / APU 790** | 支持最高 330 亿参数端侧部署（通义千问已适配）|
| **Apple M5** | 16 核 Neural Engine，**45 TOPS**，统一内存带宽 153 GB/s（+30% vs M4）<br>M5 Pro/Max/Ultra 预期用 SoIC-mH 封装分离 CPU/GPU |
| **Snapdragon X2 Elite** | NPU 吞吐约翻倍至 80 TOPS（PC 侧） |

> ⚠️ **命名陷阱**：存在低端"Snapdragon 8 Gen 5"（无 Elite）与"Snapdragon 8 Elite Gen 5"混淆，
> 前者沿用旧 Hexagon NPU。选型时必须确认完整型号。

**第三方实测**：Google LiteRT 在小米 17 Pro Max 上，**56+ 模型在 NPU 上延迟 <5ms**，
而 CPU 上只有 13 个模型达标；NPU 延迟为 CPU 基线的 **1–20%**。

### 5.2 异构分工共识

```
CPU              → 通用调度
GPU              → 高吞吐并行
NPU              → 低功耗 INT8/INT4 量化推理
DSP              → 多媒体
always-on hub    → 常时感知
```

> 行业共识：**边缘真正稀缺的不是算力，而是功耗、内存带宽和数据搬移成本。**

### 5.3 存算一体 / 近存架构（前沿）

**Cambricon-LLM**：基于 chiplet 的混合架构，面向最高 **70B 参数**的端侧推理，
把 NPU 与专用 NAND flash 芯片集成，降低处理与存储间的数据搬运开销。

### 5.4 "真 AI 手机"的产业标准（国内口径）

```
✓ 独立 NPU
✓ 旗舰算力 ≥ 100 TOPS
✓ 支持运行 70 亿参数以上模型
✓ 端侧推理速度 ≥ 10 token/s
✓ 图像生成 < 2 秒
```

当前主流旗舰 SoC 的 NPU 算力已普遍突破 **50 TOPS**，可满足 7–13B 量级需求。

> ⚠️ 对比 IDC 的定义（NPU ≥ 30 TOPS 即算"AI 手机"）——**两个标准差一倍多**，
> 引用渗透率数据时必须核对用的是哪个口径。

## 六、边缘部署的「四堵墙」框架

一篇 2026 年初综述给出的归纳，可作为工程 checklist：

| 墙 | 本质 | 对策 |
|---|---|---|
| **内存墙** | 显存 / 带宽 | 量化、剪枝、知识蒸馏 —— 降低权重加载开销 |
| **二次方墙** | 上下文复杂度 O(n²) | GQA、滑窗、稀疏注意力 |
| **计算墙** | 延迟 / FLOPs | 投机解码、PagedAttention、切分 |
| **热墙** | 功耗 / TDP | 软硬协同（NPU / FPGA 加速），保证电池环境可持续 |

**热墙最容易被低估**：持续推理让手机快速升温触发降频，
生产代码**必须**做推理时长限制和温度监控，否则 benchmark 跑分和真实体验会严重背离。

## 七、端侧个性化与隐私（研究侧）

技术栈已经成型：**LoRA 适配器 + 联邦学习 + 差分隐私 + 机器遗忘**。

| 方向 | 代表工作 |
|---|---|
| 联邦 LoRA | Heterogeneous LoRA、FLoRA (NeurIPS 2024)、RBLA、AutoRank（异构秩聚合） |
| 资源受限端侧微调 | MobiLLM（服务器辅助）、PocketLLM |
| 分割 + 联邦混合 | Flexible Personalized Split Federated Learning (arXiv:2508.10349) |
| 差分隐私 | DP-FedLoRA (arXiv:2509.09097) |
| **可删除适配器** | arXiv:2604.21571 —— 可组合 LoRA + 可删除用户代理，连接 LoRA 组合与机器遗忘 |
| 防遗忘 | 稀疏正交 LoRA，正交约束防适配器间灾难性遗忘 |

**最值得关注的是「可删除适配器」方向**：它给"被遗忘权"提供了技术基础——
用户可以在本地删除自己数据的影响，**无需重训全局模型**。这在合规上的价值可能超过其技术价值。

**开放威胁**：成员推断攻击、投毒攻击、模型反演攻击；
高维模型差异下的严格 DP 保证仍未解决；目标是 **<1KB/轮**通信（量化/稀疏化/零阶更新）。

## 八、开放问题（研究选题参考）

1. **端侧 MoE 的 offloading**：所有专家装不进内存这件事没有被真正解决
2. **2-bit 以下的表示学习**：ParetoQ 发现低比特模型学的是本质不同的表示——那它学的到底是什么？
3. **Mamba / SSM 在端侧的三重困难**：算力与带宽需求可观、循环特性天然限制并行、量化剪枝因选择性状态空间与非线性组件交互而更复杂
4. **面向边缘的分布式解码策略**：split inference 和投机解码有进展，但端云分布式解码仍探索不足；prefill/decode 分离有望减少阶段间干扰
5. **跨框架 NPU 性能特征**：同一 NPU 在不同框架下表现差异巨大，**没有统一基准**
6. **test-time compute 用在小模型上**：理论尚不清楚
7. **学术原型与量产的鸿沟**：大量软硬协同设计只在仿真或特定 ASIC 原型上验证，通用硬件上用不了
