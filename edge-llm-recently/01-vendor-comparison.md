# 端侧模型厂商横向对比：面壁 vs 友商

> 调研日期：2026-09-16
> 每条数据标注来源类型：【官】厂商官方 /【三】第三方实测 /【媒】媒体报道 /【估】预测或宣称

---

## 一、四类玩家的商业模式差异

端侧这个赛道的玩家不是同一种生意，直接比分数会比错。

| 类型 | 代表 | 收入来源 | 真实竞争力 | 死穴 |
|---|---|---|---|---|
| **独立供应商** | 面壁、Liquid AI | 模型授权 + 定制 | 密度、适配广度、中立性 | 平台方自带模型后被挤压 |
| **大厂开源** | Qwen、Gemma、Phi、SmolLM | 不直接收费（生态/云引流） | 生态、尺寸齐全、免费 | 不做深度端侧适配 |
| **手机厂自研** | vivo、华为、小米、OPPO、荣耀 | 卖手机 | 系统级权限 + 数据闭环 | 模型研发成本高、只服务自家 |
| **OS 平台方** | Apple、Google、Microsoft | 卖设备/OS | 定义 API，独占系统位 | 迭代慢、保守 |

**关键判断：面壁的对手不是 Qwen，而是「OEM 自研」和「平台自带」。**
Qwen 免费开源反而帮面壁教育了市场；真正抢单的是 vivo 蓝心这类自研，和 Gemini Nano 这类系统自带。

## 二、面壁 MiniCPM 产品矩阵

| 模型 | 参数 | 定位 | 关键指标 | 时间 |
|---|---|---|---|---|
| **MiniCPM5-2B** | ~2.52B | 端侧 Agent 基座（旗舰） | AA 榜 17 分，宣称 4B 以下全球第一【官】<br>原生 131072 上下文，宣称 512K 超长窗口【官】<br>标准 Llama 稠密 Transformer | 7/19 WAIC 发布<br>9/07 开源 Apache-2.0 |
| **MiniCPM5-1B** | ~1B | 极致轻量文本基座 | AA-Index 17.9【官】<br>FlagOS 上适配 9 款芯片（含 ARM）【官】 | 5/25 开源周 |
| **MiniCPM-V 4.6** | 1.3B | 端侧多模态 | 6GB 内存手机流畅运行【官】<br>iOS / Android / HarmonyOS | — |
| **MiniCPM-o 4.5** | 9B | 全双工全模态 | 语音+视频+文本同步交互<br>OpenCompass 8 项平均 77.6【官】 | — |
| **AgentCPM-GUI** | — | GUI 智能体 | 稀疏思考（Sparse-Thinking），避免每步长 CoT | — |
| **VLA 具身模型** | — | 机器人 | 与 SuperMate 同期发布 | 7 月 |

### MiniCPM5-2B 的训练配方（这是它真正的差异点）

```
预训练 → 200B 规模 Agent Midtraining
       → 百万条高质量轨迹 Agent SFT
       → Agent RL 对齐优化
```

**为什么重要**：绝大多数 2B 级模型的后训练还停留在通用 SFT + 偏好对齐。
面壁把 200B token 的预算专门投给 Agent 中期训练，是拿"通用能力"换"工具调用 + 多步规划"。

这解释了一个现象：MiniCPM5-2B 在通用榜（AA）分数高，
但在偏中文日常场景的 SuperCLUE OnDevice 上被 vivo 蓝心 3B 压过——**这是配方取舍的直接后果，不是模型不行。**

## 三、逐个对手拆解

### 阿里 Qwen3.5 小尺寸系列 —— 生态压制

| 项 | 内容 |
|---|---|
| 开源时间 | 2026-03-02，0.8B / 2B / 4B / 9B 四款，Apache 2.0【官】 |
| 架构 | DeltaNet 为核心的混合注意力；9B 为例，每 4 层 3 层线性注意力 + 1 层全注意力【官】 |
| 多模态 | **全系原生视觉**，预训练阶段早期融合（Early Fusion），非后挂视觉编码器【官】 |
| 上下文 | 原生 256K【官】 |
| 端侧实测 | 4bit 后 0.8B ≈ 533MB，2B ≈ 1.37GB；Apple Silicon 纯 CPU 4 线程，0.8B ≈ 140 tok/s【三】 |
| 极限 | 0.8B / 2B INT4 可在树莓派 5 或旧手机运行【三】 |
| 生态 | Unsloth 首日放出全系 GGUF（2-bit 到 8-bit）【三】 |

**对面壁的威胁评估：**
- 🔴 **最大威胁**：免费 + Apache 2.0 + 全系多模态 + 量化版首日就绪。任何 OEM 都会先试 Qwen。
- 🟢 **面壁的缝隙**：Qwen 不做**芯片级适配和交付服务**。OEM 拿到 GGUF 之后，把它跑进自家 NPU 那段工程量才是面壁卖的东西。

> 社区意见：有开发者认为 2B 与 4B 尺寸过近、10B 以下过于密集，建议补 14B。

### vivo 蓝心 BlueLM —— 端侧自研标杆

- 3B 端侧模型；SuperCLUE OnDevice 手机端侧第一 **89.86**，超过 Qwen3.5-9B（87.82）和 4B（85.16）【三】
- 鲁大师 AI 榜 386602 分，领先同级【三】
- 路线：小参数 + 模型压缩 + 精度恢复，公开话术是打破"模型小、能力强、功耗低"的不可能三角

**这个数据点很关键**：3B 端侧模型在端侧场景榜上打过 9B 云端级模型。
说明**端侧场景榜考的是"场景贴合度"而非"通用智能"**，深度系统集成的收益大于参数量。
云端顶尖（Gemini 3.6 Flash 93.64）与本地 3B 的分差已缩到约 4 分——**端侧过了"够用"阈值**。

### 其他手机厂商

| 厂商 | 模型 | 2026 差异化 |
|---|---|---|
| 华为 | 小艺（盘古） | HarmonyOS 6.1 伴随式 AI、屏幕感知；主动式 AI 最"无感"【媒】 |
| 小米 | 澎湃 AI / MiMo | 澎湃 OS 4 把 MiMo 融入系统底层；系统 AI 重构最全面【媒】 |
| OPPO | AndesGPT | 首发 AI 健康档案；宣称端侧 200 tokens/s【官】 |
| 荣耀 | 魔法大模型 / YOYO Next | 开放自定义模型 + 技能商店，唯一做生态开放的【媒】 |

> ⚠️ 上表的"最无感/最全面"等评价来自媒体横评，主观性强，不建议作为决策依据。
> OPPO 的 200 tokens/s 未说明模型尺寸、量化精度和测试机型，**不可比**。

### Apple AFM 3 —— 架构上最激进

```
AFM 3 Core           3B  稠密   端侧（全部 Apple Intelligence 机型标配）
AFM 3 Core Advanced  20B 稀疏   端侧，每次激活 1–4B ← 最重要的一条
AFM 3 Cloud          —          Private Cloud Compute
AFM 3 Cloud Pro      —          跑在 Google Cloud 的 NVIDIA GPU 上，用 Gemini 输出做精炼
```

- 发布：WWDC26 keynote，2026-06-08 随"Siri AI"上线
- 稀疏机制：**Instruction-Following Pruning**（指令跟随剪枝），苹果明确表述为剪枝而非 MoE 路由
- 框架开放：Foundation Models 框架支持通过 LanguageModel 协议接入**任意模型**（含 Claude、Gemini），支持多模态图像 prompt 和 Dynamic Profiles 会话中换模型
- 2026 夏季框架开源 + Linux server 支持 —— **开源的是框架，权重不开源**
- LoRA 适配器支持动态加载热交换

> ⚠️ 20B / 1–4B 激活的数字**主要来自第三方开发者拆解**，Apple ML Research 官方页未确认。引用前请核原始来源。

**对行业的影响**：苹果证明了端侧可以放 20B 级模型。如果这条路可复制，
"端侧只能 3B"的前提就没了，所有押注"小参数密度"的厂商都要重新算账——**这是对面壁叙事最实质的挑战。**

### Google Gemini Nano —— 架构上最聪明

- 跑在 **Android AICore 系统服务**中，**全设备所有 App 共享同一份模型**——避免重复下载和存储浪费
- 上层 ML Kit GenAI API：Prompt / 摘要 / 校对 / 改写 / 图像描述 / 语音识别，支持流式与非流式
- Nano 3 需 12GB+ RAM 和旗舰芯片；标准 XS 构建约 100MB，XXS 为其四分之一（仅文本）
- 实测：Galaxy S26 上 4.2GB 基础模型一次 Wi-Fi 下载后完全离线运行【三】
- 已知坑：AICore 原始 API 在 Nano 3 上报 `RESPONSE_PROCESSING_ERROR`，官方推荐走 ML Kit；摘要限 3 个要点；图像描述仅英文

**"系统共享单一模型"是对第三方模型供应商最大的结构性威胁**——
一旦 Android 生态里所有 App 都默认调 AICore，OEM 采购第三方端侧模型的动机就只剩"差异化"这一条。

### Liquid AI LFM2.5 —— 架构路线上唯一的异类

- 系列 350M–24B，端侧优化；LFM2.5-1.2B 提供 Base / Instruct / 日语 / VL / ALM 变体
- 架构：**门控短卷积块**（gated short convolution）降延迟，非标准 Transformer
- 预训练从 10T 扩到 **28T tokens**，扩大 RL 后训练
- 定位不是通用聊天，而是**工具调用、数据抽取等具体任务**
- 通过偏好对齐 + RL 修复 "doom looping"（循环复读）问题

**它提出的一个尖锐观点值得记：**

> Gemma 3 270M 约 **63%** 参数在 embedding 层，Qwen3.5-0.8B 约 **29%**，而 LFM2 只有约 **10%**。
> embedding 参数不像其他参数那样贡献推理和知识容量，**所以"有效模型大小"远小于参数量**。

这是对"按参数量比模型"这个习惯的直接反驳。比 0.8B 模型时，
真正在干活的可能只有 0.57B（Qwen）对 0.72B（LFM）——**差距被参数量标签掩盖了**。

## 四、榜单口径对照表（选型必读）

| 榜单 | 偏向 | 谁占优 | 适合什么决策 |
|---|---|---|---|
| **Artificial Analysis / AA-Index** | 通用智能、Agent 能力 | MiniCPM5 | 选 Agent 基座 |
| **SuperCLUE OnDevice** | 中文手机实际场景 | vivo 蓝心 | 选手机助手模型 |
| **OpenCompass** | 学术综合 | MiniCPM-o | 论文对比 |
| **鲁大师 AI 榜** | 设备综合跑分 | vivo | 参考价值低 |

**同一批模型在 AA 和 SuperCLUE 上能排出相反顺序。**
看到"全球第一"先问：哪个榜、哪个尺寸段、什么日期版本、谁跑的。

## 五、面壁的护城河与风险（尽量客观）

### 护城河

1. **唯一的第三方备案身份**——7 款手机端侧 AI 备案中，唯一非 OEM 非平台方的模型供应商
2. **芯片适配广度**——高通、英特尔、联发科、瑞芯微、天数智芯、中科创达、安波福；FlagOS 9 款芯片
3. **车机双线**——手机（三星）+ 座舱（吉利、上汽大众、广汽、长安马自达），座舱是目前量产最快的方向
4. **Agent 训练配方**——200B Agent Midtraining 这种投入，小公司做不了，大厂不屑于给 2B 模型做
5. **学术背书**——Densing Law 上了 *Nature Machine Intelligence* 封面

### 风险

1. **平台自带模型的挤压**——Gemini Nano 的系统共享架构、Apple 的 20B 稀疏端侧模型，都在压缩第三方空间
2. **Qwen 的免费碾压**——全系多模态 + Apache 2.0 + 首日量化版，OEM 的默认起点
3. **财务黑箱**——估值 200 亿，营收/毛利/净利全部未披露；"30 万台量产车"是搭载量不是收入
4. **三星合作未官宣**——目前仅媒体独家报道，双方无联合公告
5. **叙事依赖 Densing Law**——如果 Apple 的稀疏端侧路线成立，"参数越小越好"的前提本身会动摇

## 六、一页速查

```
选型决策树：

需要中文手机场景开箱即用？ → vivo/华为/小米 自研（但你买不到）
需要免费 + 生态 + 多模态？ → Qwen3.5-0.8B/2B/4B
需要端侧 Agent / 工具调用？ → MiniCPM5-2B
需要极致小 + 非 Transformer 效率？ → Liquid LFM2.5-1.2B
需要 iOS 原生？           → Apple Foundation Models（AFM 3 Core, 3B）
需要 Android 原生？       → Gemini Nano via ML Kit GenAI
需要芯片适配交付服务？     → 面壁（这是它真正卖的东西）
```
