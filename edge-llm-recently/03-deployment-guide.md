# 端侧大模型落地指南：端云协同、Agent、工程陷阱与选型

> 调研日期：2026-09-16
> 面向：要真的把端侧模型放进产品的人

---

## 一、端云协同：2026 年的主流形态不是"替代"，是"分层"

### 1.1 生产系统的真实数据

**60–80% 的 LLM 查询已被路由到端侧模型**，延迟控制在 20ms 以下。
学术侧的对应判断：**70–80% 的生产查询不需要前沿模型**。

### 1.2 一个可直接抄的分界点（语音 AI 案例）

```
查询 < 50 token          → 本地 7B，  < 200ms
更长 / 多步推理           → 云端 70B，  350–400ms
结果：70–80% 流量留在端侧
```

### 1.3 产业界总结的三层形态

```
┌─────────────────────────────────────┐
│ 记忆层（个性化）                       │  ← 用户画像、长期偏好
├─────────────────────────────────────┤
│ 云端大模型（兜底）                     │  ← 前沿推理、广博知识、长多轮
├─────────────────────────────────────┤
│ 端侧小模型（驻留）                     │  ← 高频、低风险、强实时
└─────────────────────────────────────┘
```

**端侧小模型的要求不是"最顶尖"，而是「够用、够稳、够省电」。**
理想设计是简单任务走本地、复杂任务走云端，**用户感知不到切换**。

### 1.4 路由层正在从静态规则变成学习系统

| 阶段 | 做法 |
|---|---|
| 旧 | 静态分类器 + 手调阈值（如 token 长度） |
| **新** | **上下文多臂赌博机**，基于实时成本/延迟/质量反馈动态优化 |

相关工作：Hera (arXiv:2605.24598)、ConsRoute (arXiv:2603.21237)、HERA (arXiv:2504.00434)、
ACM Computing Surveys 端云协同综述 (arXiv:2507.16731)。

### 1.5 分工边界（可作为设计原则）

| 放端侧 | 放云端 |
|---|---|
| 格式化、轻量问答、摘要 | 前沿推理 |
| 延迟敏感 | 广博世界知识 |
| 隐私关键 | 长多轮对话 |
| 高频高量（省成本） | 低频但要求高质量 |

**Apple 的参考实现**：3B 端侧模型处理个人数据，
Private Cloud Compute 处理复杂查询（端到端加密、无数据持久化）。

## 二、端侧 Agent：2026 年最有价值的增量场景

### 2.1 为什么 Agent 必须在端侧

GUI Agent 的技术栈分三层：

```
感知层 → 多模态模型实时分析屏幕截图、识别 UI 元素
决策层 → 规划操作步骤
执行层 → 通过 ADB 或系统级权限注入点击、滑动、输入事件
```

**执行层需要系统级权限，感知层需要毫秒级反馈——这两条都把 Agent 按在端侧。**
这是端侧模型第一次拥有云端难以替代的场景。

### 2.2 最大瓶颈：Token 爆炸与多跳延迟

高分辨率截图 + 长上下文 → token 激增；
规划、定位、验证多模块多跳推理 → 端到端延迟远超人类操作。

**两条应对路线：**

| 路线 | 做法 | 代表 |
|---|---|---|
| **端云协同** | 端侧小模型/7B 蒸馏模型处理高频简单点击，云侧大模型接管复杂重规划 | Mobile-Agent-v3.5、MAI-UI、Fara-7B |
| **动作空间/Token 压缩** | 紧凑动作空间；仅在不确定节点激活**稀疏思考（Sparse-Thinking）**，避免每步长 CoT | **AgentCPM-GUI（面壁）**、Game-TARS |

> Sparse-Thinking 这个思路值得单独记：**不是每一步都需要推理，只在分叉点推理**。
> 这对端侧的 token 预算是决定性的优化。

### 2.3 玩家路线分化

| 方案 | 主导 | 路线 |
|---|---|---|
| AutoGLM 2.0 | 智谱 | 开源手机通用 Agent，云端虚拟手机/电脑，覆盖 50+ 高频中文 App |
| 豆包手机助手 | 字节 × 中兴 | **系统级权限集成**，高权限跨应用操作 |
| AppAgent | 腾讯 | 自主探索 App 功能并生成知识库 |
| Qwen-UI-Agent | 阿里 | GUI 基座模型，截图进 / 动作出，不需 API；基于 100+ 台真机、150+ 应用构建训练与评测环境；宣称真机 92.2% |
| Pixel 10 + Gemini | Google | **保守的 API 驱动路线**，走官方意图框架，规避高权限风险 |

**GUI 与 API 两条路的取舍：**
- GUI 通用性高但效率低，长步骤误差易传递
- API 高效但缺乏通用性
- → **需要两者无缝切换**，这是目前的工程难点

### 2.4 系统级权限的安全争议（重要）

厂商用系统私钥签名把助手做成 OS 的一部分，才有丝滑的跨应用体验。
**但该权限可直接向输入流写入触控和按键事件。**

> 危险之处在于**不可分辨性**：恶意软件若拿到该权限，
> 可绕过银行、游戏等 App 的输入合法性识别。

这是端侧 Agent 产业化必须先解决的问题。产业观点认为量产要过三关：

| 关 | 门槛 |
|---|---|
| 合规关 | 需出台"终端 Agent 权限白名单"标准 |
| 成本关 | "NPU + 大模型授权 + 内存溢价"导致的整机成本增幅不能超过 8% |
| 价值关 | 必须跑出 DAU > 30 万的杀手级应用 |

> ⚠️ 8% 和 30 万这两个数字来自二手分析文章，属于个人观点，不是行业标准。

## 三、端侧 VLA 与智能座舱

座舱是目前**端侧模型量产推进最快**的场景，比手机还快。

### 3.1 通用架构模式

```
System 2（LLM 规划器）  →  分解目标           ← 可在云或端
System 1（轻量视觉运动策略）→ 30–50Hz 执行     ← 必须端侧
```

### 3.2 关键约束与方案

| 问题 | 数据 |
|---|---|
| 延迟 | OpenVLA on Jetson AGX Orin **>1 秒** |
| 内存 | 4–8 GB |

| 方案 | 效果 |
|---|---|
| GigaBrain-0-Small | SmolVLM2 骨干，行为专家约 100M 参数，针对 Jetson AGX Orin 优化 |
| EdgeVLA (EVLA) | 端侧 VLA 推理加速 |
| **EcoVLA** | 设备-边缘协同、分阶段抽象、中间张量轻量传输，**能耗效率提升最多 236%**，20Hz 动作输出下满足 SLO |
| vla.cpp | 统一推理框架，支持 1-bit VLA 量化和结构化剪枝 |

### 3.3 商业落地（CES 2026 起）

| 方案 | 特点 |
|---|---|
| **面壁 SuperMate / cpmGO** | 业界首个座舱纯端侧汽车助手；2026 年底预计超 30 万台量产车 |
| Garmin Unified Cabin 2026 | 单 SoC 上的 Android Automotive，多意图多语言对话 + 动作模型驱动座椅感知音频/显示路由 |
| LG AI Cabin Platform | 基于 Snapdragon Cockpit Elite，端侧 GenAI **无云依赖** |
| NVIDIA TensorRT Edge-LLM | 汽车/机器人推理栈，Bosch、ThunderSoft、MediaTek CES 2026 展示 |

**硅厂策略已收敛**：NVIDIA、Qualcomm 等开始用统一的"**物理 AI**"词汇
跨越机器人和自动驾驶，把 VLA 推理当作边缘芯片的核心工作负载假设。

## 四、工程陷阱清单（部署前必读）

### 🔥 陷阱 1：算子不匹配吃掉 80% 性能

> **端侧推理性能瓶颈约 80% 源自硬件与模型算子不匹配，导致性能下降 50% 以上。**

**对策**：选型阶段就要在**目标芯片**上跑实测，不要信通用 benchmark。

### 🔥 陷阱 2：TOPS 数字无法预测 LLM 速度

解码受内存带宽限制。**选设备的优先级应该是：内存带宽 > GPU/VRAM > NPU TOPS。**
一台内存大但 NPU 弱的机器，通常比高 TOPS 但内存有限的机器更能跑大模型。

### 🔥 陷阱 3：发热降频

持续推理快速升温 → 降频 → 实际吞吐远低于跑分。
**生产代码必须做推理时长限制和温度监控。**

### 🔥 陷阱 4：碎片化远超预期

**同为 Snapdragon 8 Gen 2，不同厂商的 NPU 驱动行为不一致。**
测试矩阵必须按"芯片型号 × OEM × 系统版本"三维展开，不能只按芯片型号。

### 🔥 陷阱 5：模型更新的工程成本

端侧模型一旦部署，更新要重新下载数百 MB 到数 GB，还要处理版本兼容。
**模型版本管理必须在 v1 就设计，不能后补。**

### 🔥 陷阱 6：KV Cache 把内存吃爆

长上下文下 KV-cache 占用可**超过模型权重本身**。
实测故障：CPU 推理频繁缺页 → 性能骤降；GPU 推理 → **设备崩溃重启**。

### 🔥 陷阱 7：上下文窗口数字不代表可用长度

> context-window 数字**不保证模型均匀地用好长 prompt 的每一部分**。
> 实际内存与速度还取决于精度、量化、运行时、硬件、batch size 和推理 token 量。

面壁 MiniCPM5-2B 的"原生 131072 / 宣称 512K"就是一个需要实测验证的例子。

## 五、选型决策流程

### Step 1：先定硬件预算，不是先选模型

```
内存预算（决定能装多大）
  └→ 4GB 可用：  0.8B–1.5B @ INT4
  └→ 6GB 可用：  2B–4B   @ INT4   ← MiniCPM-V 4.6 / Qwen3.5-2B 的位置
  └→ 8GB+：      4B–8B   @ Q4_K_M ← Phi-4 Mini 的位置
  └→ 统一内存 16GB+（Mac/PC）：可上 20B 稀疏或 9B 稠密
```

### Step 2：按场景选榜单，不是按榜单选模型

| 你的场景 | 看哪个榜 |
|---|---|
| 端侧 Agent / 工具调用 | Artificial Analysis、AA-Index |
| 中文手机助手 | SuperCLUE OnDevice |
| 多模态理解 | OpenCompass |
| **真实决策** | **在目标芯片上自测** |

### Step 3：量化档位

```
Q4_K_M  ← 2026 移动端标准档，保留 ~95% 质量，1/4 体积
Q8      ← 内存充裕、要精度时
2-bit   ← 研究/极限场景，注意模型学的是不同的表示
1.58-bit ← 只有从头训练的 BitNet 系可用，不能后量化现成模型
```

### Step 4：运行时

| 目标 | 选择 |
|---|---|
| 快速验证 / 桌面 | llama.cpp、Ollama、LM Studio（**不走 NPU**） |
| Android 生产 | MNN-LLM、MediaPipe/LiteRT、ExecuTorch |
| Android 系统级 | AICore + ML Kit GenAI（Gemini Nano，全 App 共享） |
| iOS / macOS | Foundation Models 框架（AFM 3 Core）、MLX |
| Windows | Foundry Local（自动选硬件和模型变体） |
| 要榨 NPU | 厂商 SDK（QNN/GENIE）或手动 ONNX + EP 编译 |

### Step 5：端云路由

从静态规则起步（token 长度 + 意图分类），埋好埋点，
**攒够数据后再换成学习型路由**（上下文多臂赌博机）。不要一上来就做复杂路由。

## 六、三个场景的推荐配置

### 场景 A：手机 App 里的轻量助手

```
模型：Qwen3.5-2B @ Q4_K_M（~1.37GB）或 MiniCPM-V 4.6（多模态，6GB 内存）
运行时：MNN-LLM 或 ExecuTorch
路由：短查询本地，长/复杂走云
注意：加温度监控 + 推理时长限制
```

### 场景 B：端侧 Agent / GUI 自动化

```
模型：MiniCPM5-2B（Agent 训练配方）或 Qwen-UI-Agent
策略：Sparse-Thinking，只在分叉点推理
架构：端侧处理高频简单点击，云端接管重规划
风险：系统级权限必须有白名单和审计
```

### 场景 C：智能座舱

```
模型：MiniCPM-o 4.5（全模态）或 SuperMate 方案
架构：System 2 规划（可云可端）+ System 1 执行（必须端侧，30–50Hz）
硬件：Snapdragon Cockpit Elite / 瑞芯微 AI Box / Jetson
特点：这是目前量产最快的端侧场景，比手机成熟
```

## 七、什么时候**不该**用端侧模型

诚实地说，以下情况云端仍然更好：

- ❌ 需要前沿推理能力（数学证明、复杂代码）
- ❌ 需要广博世界知识（端侧模型的知识容量是硬约束）
- ❌ 长多轮对话（KV cache 会吃爆内存）
- ❌ 低频调用（端侧的成本优势来自高频摊薄，低频时不值得付出工程代价）
- ❌ 模型需要频繁迭代（端侧更新成本高）

**端侧的四个真实理由**：延迟、隐私、成本（高频时）、离线可用。
如果你的场景不占其中至少两条，先别做端侧。
