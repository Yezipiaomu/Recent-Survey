# 成本与选型：70 倍 token 差从哪来，以及怎么选

> 调研日期：2026-09-16 · [返回索引](README.md)
> 一句话结论：**在头部分数打平（61/60/60）之后，harness 之间唯一还有数量级差异的维度是成本——
> 同一个模型换个壳，token 用量能差 70 倍。而且成本无法预估、失败任务更烧钱。**

---

## 1. 核心数据：harness 比模型更决定账单

> **Aider、Claude Code 和 OpenClaw 跑同一个模型，token 使用量相差 70 倍。**
> 同一测试中 Aider 消耗约 **80 万** token，Codex 花了 **1500 万**。

⚠️ **可信度**：该测试只有 **10 个任务**，样本较薄，**仅作方向性参考**。
但 70 倍这个量级即便打个大折扣，也远超模型能力差异能弥补的范围。

---

## 2. 根因：Context 这一职责还停在最朴素的实现

```
第 1 轮：  [系统提示] [用户请求]
第 2 轮：  [系统提示] [用户请求] [工具调用1] [返回1]
第 3 轮：  [系统提示] [用户请求] [工具调用1] [返回1] [工具调用2] [返回2]
   ...
第 N 轮：  ████████████████████████████████████  逼近上限才开始压缩
```

> 当前产品级 coding agent **大多仍采用最朴素的「全盘累积」策略**——
> 每次代码查询、每份文件内容、每条工具返回结果都追加进对话历史，
> 下一轮**原封不动重新喂给模型**，直到逼近上下文上限才开始压缩。

**任务越长雪球滚得越大，即便启用缓存，输入端仍是开销主力。**

这是 [agent-harness-2026-09.md](agent-harness-2026-09.md) 六职责框架里 **Context** 一轴的全部内容，
也是目前最大的工程洼地：**谁先做对上下文压缩，谁就拿走 40–70% 的成本优势。**

## 4. 缓存与并行：两个容易被忽略的乘数

### 4.1 缓存

| 场景 | 成本 |
|---|---|
| 同一 bugfix，Sonnet 4.6 **有缓存** | **$0.54** |
| 同一 bugfix，Sonnet 4.6 **无缓存** | **$1.35** |

Claude Code 会**自动启用缓存**。

> 呼应 [../llm-recently/README.md](../llm-recently/README.md) 的结论：
> **agent 负载选型看 cache read 单价，不看 token 单价。**
> 该报告给出 DeepSeek V4.1-Flash cache read $0.003 vs Kimi K3 $0.30 —— **约 100 倍**。
> 把「harness 的 context 策略」和「模型的 cache read 定价」两个因素乘起来，
> 才是真实账单。

### 4.2 并行的代价

> **每个并行会话是独立对话，彼此不共享缓存。**

| 并行度 | 相对 token 消耗 |
|---|---|
| 1 会话 | 1× |
| 3 会话 | **约 3×** |
| Agent Teams（plan mode） | **约 7×** |

→ **「多开几个窗口并行干」不是免费的**，它按线性甚至超线性放大账单。

### 4.3 省钱杠杆

**路由 + 压缩通常可削减 40–70% 的 API 支出。**

## 5. 实际花费量级

| 人群 | 月度 |
|---|---|
| 独立开发者（诚实答案） | **$20–100/月** 订阅即可 |
| 重度自动化 | **$500–2,000 / 工程师 / 月** |
| Anthropic 自报企业数据 | 约 **$13 / 开发者 / 活跃日**，即 **$150–250/月**；**90% 用户在任何活跃日低于 $30** |

订阅起步价 $20/月（Claude Pro、Codex Plus），但**单个任务会推送 40 万到 200 万累计输入 token**。

**商业模式差异**：

- **订阅制托管**：Claude Code、Codex（Codex 企业版 2026-04 起转为 token 计费信用制）
- **自托管、只付模型 API**：OpenCode、Qwen Code、Goose、OpenHands
  → 但**沙箱、凭据和审计链路都要自己搭**，这是隐性成本
- **积分制**：AutoClaw（不按 token）
- **近乎白送**：ArkClaw（Coding Plan Lite 首月 ¥9.9，Pro 订阅期内 ArkClaw 永久免费）、
  Trae 国内版（核心功能免费无限制，需排队）

## 6. 两个反直觉发现

### 6.1 成本无法预估

> 有研究按 token 开销对任务排序，与人类标注难度计算相关性，
> **Kendall τ = 0.32** ——人类专家对任务难度的判断与 agent 实际 token 消耗**只有很弱的相关性**。

→ **不要用"这个任务看起来简单"来预估预算。**

### 6.2 失败的任务更烧钱

> **所有模型在失败任务子集上的 token 消耗都多于成功子集。**

→ 成本与成功率是**负相关**的：越是做不出来的任务，越会反复试错、越烧钱。
这意味着**提高成功率本身就是最有效的省钱手段**，比换便宜模型更直接。

## 7. 选型建议

### 7.1 按场景

| 场景 | 选 | 理由 |
|---|---|---|
| 复杂多文件重构、要和 AI 一起推演 | **Claude Code** | 推理深度占优；Skills/Subagents/Agent Teams 三层编排 |
| 派活异步跑、要并行 + 强审批边界 | **Codex** | 内核层沙箱 + 云端按任务起容器 + token 效率高 2–4 倍 |
| 不接受厂商锁定、要自己接模型 | **OpenCode** | MIT、75+ provider、LSP 诊断回灌 |
| 想自己拼一个 Agent | **DeepSeek Harness** | 一切皆插件；但仍是 Developer Preview |
| 要在 IDE 里随时换 Agent | **认准 ACP 支持** | 见 [01-protocol-layer.md](01-protocol-layer.md) |
| 个人 24h 助理 | OpenClaw 系 | 但先读 [04-openclaw-security.md](04-openclaw-security.md) |
| 数据不能出内网 | AutoClaw / dsh + 本地模型 / WorkBuddy 本地优先 | |
| 非技术岗办公 | WorkBuddy | 微信扫码三步上手 |
| 零成本先跑起来 | Qwen Code / iFlow CLI / Trae 国内版 | 免费接国产模型 |

### 7.2 混用建议（社区共识）

> 团队进入日常 AI 编程阶段后通常两者都用，但**别让它们抢同一块代码**：
> **Claude Code 负责判断"为什么改、怎么拆、哪里危险"；
> Codex 负责执行边界清晰的任务、检查、复审或自动化。**

另一条实用建议：**即使只用 Claude Code，也顺手写一份 `AGENTS.md`**——
20 分钟就能让项目对 Codex、Cursor、Copilot 用户开放。

### 7.3 成本控制清单

- [ ] 确认模型的 **cache read 单价**（不是 token 单价）
- [ ] 开缓存（Claude Code 自动开）
- [ ] **别无脑开并行**——3 会话 ≈ 3×，Agent Teams plan mode ≈ 7×
- [ ] 上路由 + 压缩（可削 40–70%）
- [ ] 监控失败率——**失败任务更烧钱**，提高成功率比换便宜模型更省
- [ ] 不要按"任务看起来难不难"做预算（τ=0.32）
