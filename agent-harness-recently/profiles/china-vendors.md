## 1. 先纠正一条流传甚广的说法

> **「所有龙虾类产品都是 OpenClaw 套壳」是错的。**
>
> **只有 QClaw 基于 OpenClaw 开源框架构建。**
> **WorkBuddy 是基于腾讯自研的 CodeBuddy 智能体架构开发的，底层代码与 OpenClaw 无关**；
> 它之所以被称为"龙虾"，只是因为**兼容 OpenClaw 的技能包和 MCP 协议**，
> 目的是复用社区已有资源、降低用户迁移成本。

⚠️ 上述说法来自腾讯云开发者社区文章与媒体分析，**并非腾讯官方架构白皮书**。
严格意义的官方技术揭秘建议查阅腾讯云 CodeBuddy 官方文档或腾讯云开发者大会分享。

## 2. 腾讯：WorkBuddy / CodeBuddy / Marvis / OPC

### 2.1 四产品共用一套四层架构

```
Layer 4 应用层
 ┌──────────────┬──────────────┬──────────────┬─────────────────┐
 │  WorkBuddy   │  CodeBuddy   │   Marvis     │  OPC Platform   │
 │  办公数字员工 │  AI 编程助手  │  系统管家     │  全栈自动化      │
 └──────────────┴──────────────┴──────────────┴─────────────────┘
                          ↓  共享同一底座  ↓
          CodeBuddy 沉淀两年多的 Coding Agent 内核（Harness 层）
```

> **WorkBuddy 能够领先，主要依靠 CodeBuddy 沉淀两年多的 Coding Agent 内核，
> Harness 能力强、任务执行稳定性高。**

### 2.2 WorkBuddy

| 项 | 内容 |
|---|---|
| 定位 | AI 原生**桌面**智能体工作台；代表从"对话式 AI"向"**执行式 AI**"的范式转移 |
| 架构 | **专家 / 技能 / 插件**三大模块协同 |
| 数据 | **「本地优先」——所有自动化操作在本地执行，文件数据不上传云端** |
| 模型 | 内置 **11 种国产模型**可自由切换：腾讯混元 Hy3、智谱 GLM-5.2、Kimi-K2.7-Code、DeepSeek-V4 等 |
| 远程 | 支持通过**企业微信 / QQ / 飞书 / 钉钉远程控制办公电脑**执行任务 |
| 上手 | 下载安装 → 微信扫码登录 → 开口说需求，**三步** |
| 产品语言 | 把"技能""专家"这类术语**翻译成职场人听得懂的表达** |

**起源**：源自腾讯一个十余人的 AI 代码助手团队；**2026-01 中旬的一个周末**，
产品负责人汪晟杰和一位运营同事**熬了两个通宵做出 0.01 版本**；
公测前腾讯内部已有**超过 2000 名非技术岗员工**每天使用。

**商业数据**：

| 指标 | 数值 |
|---|---|
| 2026-06 月访问量（易观） | **2097 万**，**是第二名和第三名之和** |
| 2026-06 全平台月活 | **2000 万** |
| 日活 | **超过 1300 万** |
| 马化腾财报会表述 | "**中国使用最广的效率智能体服务**" |

### 2.3 隐忧

> WorkBuddy 定位为"Agent 时代的操作系统""工作生活总入口"，
> 与**企业微信的办公入口、腾讯文档的文档入口存在重叠**，
> 且**三者分属不同事业群，内部打通存在难度**。

### 2.4 混元 Hy3 与 Co-design

腾讯 **2026-07 正式发布混元 Hy3 模型**，与 WorkBuddy 深度适配，
形成完整国产 Agent 方案，其架构是**模型与产品 Co-design（协同设计）**的结果：

```
工具生态层（腾讯文档 / 企业微信 / 腾讯会议 / ima）
        ↓
WorkBuddy Agent 层（任务拆解、工具调度、长程状态管理）
        ↓
混元 Hy3 模型层
```

## 3. 字节：豆包 ≠ 框架

### 3.1 定位澄清（火山引擎官方口径）

| | 类型 | 能力 | 是否框架 |
|---|---|---|---|
| **豆包大模型** | **交互型** | 对话交互、多模态内容生成、代码辅助、知识问答；**需结合外部工具实现任务落地** | ❌ **是模型** |
| **ArkClaw** | **执行型** | 自主任务执行、事务处理闭环、定时任务、飞书/钉钉 Bot、TOS 快传 | ✅ |

**两者协同不竞争**：ArkClaw 依托火山方舟可无缝集成豆包 API 作为推理引擎，
在管理界面一键切换推理模型为豆包，实现「思考 + 执行」双能力。

详见 [openclaw-and-forks.md §2.2](openclaw-and-forks.md)。

### 3.2 字节的其他布局

- **Trae**（AI IDE）：国内版模型换成豆包 Seed Code / DeepSeek / Kimi 等国产模型，
  **核心 AI 编程功能完全免费无限制（需排队）**；核心亮点是 **SOLO 智能体模式**
  （自主完成需求拆解、编码、测试全流程）和 Builder 模式；
  累计注册用户 **600 万+**，月活 **160 万+**
- **DeerFlow 2.0**：开源超级智能体编排框架，子代理编排 + 插件化工具箱 + 安全沙盒 + 长效记忆，
  GitHub 约 **44k star**
- **TRAE Work**：办公任务型产品

## 4. 国产编程 CLI 四强

| 工具 | 厂商 | 开源 | 差异点 |
|---|---|---|---|
| **Kimi CLI** | 月之暗面 | ✅ | **完整支持 ACP** —— Zed 等编辑器可直接把它当 AI 后端（**国产唯一**）；MCP 深度集成；定位 **bash + AI + IDE 三位一体**，`Ctrl+K` 在 Shell 模式与 AI 模式间切换；可接 Chrome DevTools、Context7 等工具 |
| **Qwen Code** | 阿里 | ✅ | Qwen-Coder 底座，中文支持好，本地化开发场景 |
| **iFlow CLI** | 心流（阿里系） | ❌ | 对标 Claude Code；**免费接多模型**（Kimi K2 / Qwen3-Coder / DeepSeek v3）；原生 Shell 支持 + 中文深度优化；**YOLO 模式**一键自动执行；`/init` 扫描代码库生成结构化文档；开放市场一键装 **SubAgents 和 MCP**；**iflow-cli-action** 可进 GitHub Actions 自动编码与处理 issue |
| **CodeBuddy CLI** | 腾讯 | ❌ | `generate`（生成项目结构）/ `deploy`（部署到云平台）/ `architect`（系统架构设计）命令式子功能；混元 + DeepSeek 双模型；**微信小程序开发** |

### CLI 相对 IDE 插件的三个天然优势

1. **环境无关**——无论用 VS Code、Cursor 还是 Trae 都能用
2. **上下文更完整**——可直接访问整个项目目录
3. **适合自动化**——可嵌入 CI/CD、脚本、批量任务

⚠️ **Kimi CLI 安装方式已变**：现支持 macOS/Linux/Windows，官方提供一键安装脚本；
底层运行时**已从 Python 升级到 Node.js**，旧教程的 `uv tool install kimi-cli` **不再是推荐方式**。

## 5. IDE 侧「御三家」

字节 **Trae 国内版**、阿里 **Qoder**、腾讯 **CodeBuddy** 被视为国内 AI 编程 IDE 御三家，
功能比较接近，**最大的共同优势是国内直连无障碍，不需要网络工具**。
四家（含百度文心快码）都提供插件、IDE、CLI 等多端形态，基于自研大模型构建。

| 工具 | 亮点 |
|---|---|
| **Qoder**（阿里） | 自研 Qwen-Coder 底座，国内版也支持第三方模型；**Repo Wiki 自动生成项目知识图谱**，适合理解大型代码库；国内模型生态最完整 |
| **CodeBuddy**（腾讯） | 独立 IDE + VS Code/JetBrains 插件 + CLI；**与微信生态深度集成**（小程序开发、企微 Bot）；设计稿转代码、PRD 生成 |
| **Trae**（字节） | **SOLO 智能体模式** + Builder 模式；核心功能免费 |
| **通义灵码**（阿里） | 企业级成熟，VS Code 装完几乎零配置 |
| **文心快码**（百度） | 多端形态，文心底座 |

## 6. 公认差距

> - **Agent 能力**上 Cursor / Claude Code 仍领先
> - **多文件协同编辑**方面国产工具**刚起步**
> - **复杂代码推理和生态整合**也存在差距
> - （②类）**工具调用能力，尤其浏览器控制和第三方服务集成**，差距明显

对照 [六职责框架](../agent-harness-2026-09.md)：
**国产的差距集中在 Action（工具调用）和 Control（多文件/多 agent 编排）两轴**，
而在 State（本地优先、国内渠道）和商业化（免费/低价）上反而领先。
