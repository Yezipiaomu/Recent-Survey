# OpenClaw 及其国产分支档案

## 1. OpenClaw 本体

### 1.1 基本情况

| 项 | 值 |
|---|---|
| 作者 | Peter Steinberger（奥地利） |
| 沿革 | **2025-11 以 Clawdbot 发布 → Moltbot → 2026-01 更名 OpenClaw** |
| 增长 | **约 60 天突破 250,000 GitHub stars**，史上增长最快的开源项目之一 |
| 协议 | 开源、自托管 |
| 定位演进 | 个人 AI 助理 → **通用 agent 平台** |
| 2026 状态 | 持续发布 tagged release；**2026.4.x 系列主要在收拾 2 月爆红后暴露的安全问题** |

### 1.2 架构

```
┌──────────── access 层 ────────────┐  WhatsApp / Telegram / 微信 / 飞书 / 语音
├──────────── routing 层 ───────────┤  Gateway：单端口多路复用 WS + HTTP
├──────────── business 层 ──────────┤  Agent 运行时：多轮推理循环
└──────────── storage 层 ───────────┘  本地 Markdown + SQLite FTS5
```

**中央 Gateway 进程**在单一端口上多路复用 WebSocket 与 HTTP 通信，
管理会话生命周期、工具分发、渠道路由与 agent 编排。

**Agent 运行时的多轮推理循环**：模型接收对话历史与系统提示 → 生成工具调用 →
执行 → 用更新后的上下文重新提交 → 直到返回纯文本响应才结束循环。

### 1.3 三个根本差异（对比编程 harness）

| 差异 | 说明 |
|---|---|
| **常驻 + 主动** | **heartbeat 守护**是定时轮询周期，让 agent **自己醒来**巡查本地文件与远程数据库，**无需人类提示** |
| **入口是 IM 不是终端** | WhatsApp / Telegram / 微信 / 飞书；macOS、iOS、Android 支持语音交互 |
| **记忆本地化** | **不用云向量库**，改为两层本地存储：**Markdown 文件 + SQLite FTS5 全文索引** |

### 1.4 能力

| 项 | 内容 |
|---|---|
| 内置工具 | **26 个**：文件系统、shell 执行、网页搜索与抓取、浏览器自动化、记忆管理、会话控制 |
| 扩展 | **AgentSkill** 模块化系统，经 **ClawHub**（内置技能注册表）安装分发 |
| 协议 | **MCP 原生**，可接外部工具服务器 |
| 模型 | Anthropic Claude / OpenAI GPT / Google Gemini / DeepSeek；**Ollama 或任意 OpenAI 兼容端点**可完全本地隔离 |

### 1.5 按六职责定位

| 职责 | 实现 | 评价 |
|---|---|---|
| **Observation** | **heartbeat 主动巡查** + 26 工具 + 浏览器自动化 | ✅ 唯一主动的 |
| **Context** | 多轮累积 | ⚠️ 70 倍 token 测试中的高消耗方之一 |
| **Control** | 多轮推理循环 + 渠道路由 | 常规 |
| **Action** | 26 内置工具 + MCP + ClawHub 技能 | ✅ **工具调用能力仍领先国产分支** |
| **State** | 本地 MD + SQLite FTS5，**默认持久化** | ✅ 设计被认为最合理，用户控制权最大；⚠️ 但成为攻击持久化载体 |
| **Verification** | — | ❌ 基本缺失 |

### 1.6 短板

- 仅支持本地部署，依赖 **Node.js + Docker** 环境，配置繁琐，**无官方一键入口**
- 原生适配 Telegram / WhatsApp / Discord 等海外平台，**国内 IM 需第三方适配，配置复杂、稳定性差**
- **安全问题严重到触发监管动作** → [../04-openclaw-security.md](../04-openclaw-security.md)

## 2. 国产分支对比

> ⚠️ **可信度警告**：本节横评几乎全部来自自媒体或竞品方（实在智能、七牛云等），
> **倾向性明显**。具体功能描述建议以各家官方文档为准，选型建议实测验证。

### 2.1 总表

| 分支 | 厂商 | 部署 | 渠道 | 差异点 |
|---|---|---|---|---|
| **ArkClaw** | 字节火山引擎（**2026-03-09**） | **云端 SaaS** | 飞书 / 钉钉 Bot | 开箱即用零配置；定时任务；**TOS 文件快传**；**关机后任务继续跑、记忆不丢**；**不暴露公网端口** |
| **CoPaw** | 阿里通义（基于 **AgentScope**） | **本地 + 云双部署** | **钉钉/飞书/QQ/Discord/iMessage 原生** | 一键安装脚本 + 国内镜像加速（约 10 分钟）；**ReMe 长期记忆**跨会话持久化偏好、待办、决策 |
| **QClaw** | 腾讯电脑管家 | 本地，一键启动免配置 | **仅微信** | **腾讯唯一真正基于 OpenClaw 的产品**；文件操作尚可但偶有替换位置偏差 |
| **AutoClaw** | 智谱（代号"澳龙"） | **纯本地** | 飞书 | **隐私保护最好**；预装 **50+ 技能**；**按积分计费而非 token**；⚠️ 易用性不足、文件操作是短板 |
| **DuClaw** | 百度智能云 | 预期云端托管 + 私有化 | — | ⚠️ **官网仍跳错误页，预发布状态，建议观望**；不同来源说法出入大 |
| **Linclaw** | 七牛云 | — | — | ⚠️ 仅见于竞品方自评，慎引 |

### 2.2 ArkClaw 细节（唯一有官方口径的）

**定位**：「开箱即用的云上 SaaS 版 OpenClaw」，打开网页即用 7×24 在线助手。
被媒体视为字节对阿里云、腾讯相继推出 OpenClaw 类产品的**跟进**。

| 项 | 内容 |
|---|---|
| 思考模式 | **快速 / 标准 / 专家**三档，匹配不同复杂度与时效 |
| 多 Agent | 多 Agent 共用一个 Coding Plan 套餐包减少额度闲置；扩容一键完成 |
| 技能 | 内置 **Skills Hub**；支持从 **ClawHub.ai** 加载技能包（"AI Agent 的 npm"） |
| 模型 | Doubao-Seed-2.0 系列、Kimi2.5、MiniMax2.5、GLM；协同 Doubao-Seed 2.0 Pro 时复杂任务表现突出 |
| 定价 | Coding Plan Lite 首月 **¥9.9**（可免费体验 7 天）；**Coding Plan Pro 订阅期内 ArkClaw 永久免费** |

**与豆包的关系**（官方口径，[见总览 §1](../agent-harness-2026-09.md)）：
豆包是**交互型**、ArkClaw 是**执行型**，二者协同——ArkClaw 可一键把推理模型切成豆包。

### 2.3 字节的三位一体布局

有分析指出字节在此赛道是矩阵式布局：

```
飞书妙搭 OpenClaw  →  办公入口防御
ArkClaw（云虾）    →  云服务进攻
扣子 OpenClaw      →  开发生态布局
```

另：字节还开源了超级智能体编排框架 **DeerFlow 2.0**
（子代理编排、插件化工具箱、安全沙盒、长效记忆，GitHub 约 **44k star**）。

## 3. 原版 vs 国产：谁强在哪

### 原版仍领先的

- **工具调用能力**是 OpenClaw 的核心优势，国产在这方面**还有明显差距**，
  尤其是**浏览器控制和第三方服务集成**
- **记忆系统设计最合理**，给了用户最大的控制权

### 国产领先的

- 原版**仅支持本地部署**，依赖 Node.js + Docker，配置繁琐，**无官方一键入口**
- 原版原生适配海外 IM，**国内 IM 需第三方适配，配置复杂、稳定性差**
- 国产普遍提供一键安装 / 云端托管 / 国内镜像

## 4. 选型

| 场景 | 选 |
|---|---|
| 国内办公、低门槛 | **CoPaw**（钉钉飞书原生） |
| 微信重度用户 | **QClaw** |
| 数据敏感 / 隐私优先 | **AutoClaw**（纯本地）或 DuClaw（私有化，待观望） |
| 云端懒人、不想配环境 | **ArkClaw** |
| 深度定制 / 极客 / 英文生态 | **原版 OpenClaw** |

> **但在任何场景下，部署前先读 [../04-openclaw-security.md](../04-openclaw-security.md)。**
> CNCERT 已发预警，中国已限制在政府系统中使用。
